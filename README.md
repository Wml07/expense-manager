# 开销管家

一个跑在命令行里的小助手：**问它问题，它只回答你自己资料里写过的内容；资料里没有的，它直接说"资料里没写"，不含糊编造。**

---

## 怎么跑

```
cd D:\WB01\2026-08-11-10-58-12\projects\expense-manager
python zhushou.py
```

> 解释器用 `D:\python3.11.8\python.exe`（系统那个）。本机 `.workbuddy` 自带的 Python 没装 `openai` / `dotenv`，跑不起来。

跑起来长这样：

```
===== 开销管家 =====
1. 记一笔账
2. 问个问题
3. 查明细
4. 退出
请输入编号:
```

| 选 | 现在能干什么 |
|---|---|
| `1` | ✅ 记账 → 抠出数字累加 → 追加存进 `zhangben.txt` → AI 点评 + 报总额（**关掉再开，总额还在**） |
| `2` | ✅ 提问 → 去资料里检索 → 分数太低直接拦下 → 交给 AI 回答，**答案后面附来源（这次命中了哪几节）** |
| `3` | ✅ 查明细 → 逐笔列出 + 笔数 + 合计 |
| `4` | 退出 |
| 其他 | 提示重新输入，不会崩 |

```

```

以后加功能，只在 `gongneng.py` 里加函数 + 在 `zhushou.py` 加一条岔路，**互不干扰**。

## 它靠什么保证不瞎编

| 层 | 手段 | 管什么 |
|---|---|---|
| 提示词 | `SHEZHI_ZHISHI` 铁律（只根据资料回答，并交代出处） | AI **怎么说话** |
| 代码 · 第一道 | `if 最高分 < 0.5: return "资料里没写"` | **该不该说话** |
| 代码 · 第二道 | 答案后面附【来源】= 检索命中了哪几节 | **话从哪来**（让人自己核对） |

**0.5 这条线是量出来的，不是拍脑袋定的**：资料里确实有答案的问题，最高分落在 0.570 ~ 0.722；资料里压根没有的，落在 0.383 ~ 0.494。线画在两堆中间的空档里 —— 这就是阈值标定。

### ⚠️ 一次被实测否决的方案（留着当记录）

我试过更狠的办法：让 AI 用 JSON 回 `{"答案":…, "依据":…}`，代码再把「依据」拿去资料里逐字比对，找不到就判定为"编"、直接回"资料里没写"。

**实测把这个方案否了**（探针 `core/_probe_chuchu.py`）：

- 三组问题量下来，「依据命中率」是**反向**的 —— 编造的答案 **92%~100%**，真答案只有 **64%**。
- 原因：AI 的"依据"是**照抄我喂给它的那段资料**，字面当然像；真答案反而是跨块拼出来的，字面对不上。
- 更本质的：**「依据是否支撑答案」是语义问题**，字面匹配根本判定不了 —— 有个案例 AI 把依据填成"资料里没写"，照样拿了 100% 命中。

所以最后**没留硬拦**，改成**把来源摊开**：AI 说的来源它自己能编，**代码说的来源（= 检索命中哪几节）编不了** —— 让用户对着来源自己核对。

> 这条记录比代码值钱：它证明"防 RAG 幻觉不能只靠引用校验"，而**真正的根治手段在检索**（见下方"下一步"）。

## 维护须知（四条）

1. **资料改了，向量库必须重建**：`core\rag2.py` 会把 `..\学习笔记.md` 重新切成块、算成向量，覆盖 `core\xiangliang.json`。
2. **换了 embedding 模型也要重建**（新旧向量同维数，混着比**不会报错**，只会静默给出垃圾结果）。
3. **老脚本按"当前所在文件夹"找资料**：core 里的脚本在 `core\` 里运行，practice 里的脚本在 `practice\` 里运行。作品本身和 `rag2.py` 已经改成"认文件自己的位置"，换到哪跑都行。
4. **账本存的是"整句原文"**：`zhangben.txt` 每行是用户原话（如 `早饭23`），不是抠出来的数字——名字和金额都留着。金额由 `zhua_shuzi()` 现抠（记账时和启动读回时**共用一个函数**）。老数据（纯数字行，如 `20`）照样读得进，不用清账本。
