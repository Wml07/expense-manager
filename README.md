# 开销管家

跑在命令行里的一个小助手：**记账 + 只根据你自己的资料回答问题**。

两个特点：

- **记账**：说一句"早饭23"就记下了，关掉再开总额还在；
- **问答**：只答你自己资料里写过的内容。资料里没写的，它直接说"资料里没写" ——
  **这一点是靠代码保证的，不是靠提示词祈祷。**

## 它现在能干什么

| 选 | 功能 | 细节 |
|---|---|---|
| `1` | 记一笔账 | 从你说的话里抠出金额 → 累加 → **追加落盘** → AI 点评一句 + 报总额（**关掉再开，总额还在**） |
| `2` | 问个问题 | 去资料里检索 → 分数太低直接拦下 → 交给 AI 回答，**答案后面附来源**（这次命中了哪几节） |
| `3` | 查明细 | 逐笔列出 + 笔数 + 合计 |
| `4` | 退出 | |
| 其他 | 提示重新输入 | 输 `9`、输 `abc` 都不会崩 |

## 快速开始

### 1. 装依赖

```bash
pip install -r requirements.txt
```

### 2. 配 API Key

把 `.env.example` 复制成 `.env`，填上两个 key：

| 变量 | 干什么用 | 在哪申请 |
|---|---|---|
| `ZHIPU_API_KEY` | **说话**（聊天 / 人设），模型 `glm-4-flash` | 智谱开放平台，有免费额度 |
| `SILICONFLOW_API_KEY` | **变数字**（向量 / embedding），模型 `BAAI/bge-m3` | 硅基流动，这个模型免费 |

> ⚠️ `.env` 不要提交到 git，`.gitignore` 已经挡住了。

### 3. 建向量库（第一次跑必须做）

```bash
cd core
python rag2.py
```

它会把资料 `学习笔记.md` 切成块、算成向量，生成 `core/xiangliang.json`。
（这个文件是"生成物"，没进版本库 —— 换 embedding 模型后也要重建。）

> ⚠️⚠️ **资料一改，向量库必须重建。** 这条比看起来重要得多 ——
> 我踩过一次真实的坑：资料从 30 节长到 41 节，向量库却还停在 32 块，
> **后 10 节压根没进库**（包括讲 `global` 的第 37 节）。
> 表现是：问一个笔记里明明写过的知识点，程序却回"资料里没写"。
> **不报错、不崩溃，只是答案悄悄变差 —— 典型的静默错误。**
>
> 诊断脚本：`core/_probe_retrieval.py` —— 打出 top-8，直接看"正确的那一节排第几"。
> 重建前：目标节连前 8 都没进；重建后：**第 1 名**（0.537）。

### 4. 运行

```bash
python zhushou.py
```

## 代码结构（三层各管一件事）

```
zhushou.py    →  门      只管"问用户要什么"（菜单 + 分支 + 兜底）
gongneng.py   →  业务    只管"把这件事干出来"
core/tools.py →  基础设施 只管"连服务"（说话一个 client、向量一个 client）
```

| 位置 | 是什么 |
|---|---|
| `zhushou.py` | 菜单、收输入、显示结果。**菜单号和 `if shuru ==` 是绑死的，改一个必须改另一个** |
| `gongneng.py` | `wen_wenti(问题)` 检索→闸门→问 AI→附来源；`ji_zhang(说话)` 抠数字→落盘→报总额；`cha_mingxi()` 列明细；`qu_json(回话)` 把 AI 的结构化回复拆成字典；`zhua_shuzi(话)` 抠金额 |
| `core/` | `tools.py`（连服务 + 人设）、`xiangliang.json`（向量库）、一路写过来的脚本与探针 |
| `docs/` | 演示动图 + 生成它的脚本 |
| `practice/` | 全部基础练习和它们的账本数据 |

以后加功能：只在 `gongneng.py` 加函数 + 在 `zhushou.py` 加一条岔路，**互不干扰**。

## 它靠什么保证不瞎编（三道防线）

| 防线 | 是谁在管 | 手段 | 管什么 |
|---|---|---|---|
| 一 | 提示词 | `SHEZHI_ZHISHI` 铁律：只根据资料回答，且必须交代出处 | AI **怎么说话** |
| 二 | **代码** | `if 最高分 < 0.5: return "资料里没写"` | **该不该说话** |
| 三 | **代码** | 答案后面附【来源】= 检索命中了哪几节 | **话从哪来**（让用户自己核对） |

**0.5 这条线是量出来的，不是拍脑袋定的**：

| 组 | 最高分（**重建前**量的） |
|---|---|
| 资料里**有**答案 | 0.722 / 0.639 / 0.570 |
| 资料里**没有** | 0.494 / 0.444 / 0.383 |

线画在两堆中间的空白带里 —— 这就是阈值标定。（第一版拍脑袋定的 0.8 被这组数据推翻了。）

> ⚠️ **这组数据已经过期**（向量库重建前量的）。变化有两处：
> ① 重建后"有答案"那组整体上移到 **0.537 ~ 0.628**；
> ② 其中一题（"怎么监控 AI 胡说"）现在的资料里**真有答案了**（笔记第 39 节）——
> 也就是说它不该再算进"没有答案"这一组。
>
> 重新标定后：**"有答案"最低 0.537 ↔ "没答案"最高 0.555，仍然是交叠的**，
> 单靠一条线切不开。这直接把下一步指向了**扩大 top-k 或 rerank**。

### ⚠️ 一次被实测否决的方案

我试过更狠的办法：让 AI 用 JSON 回 `{"答案":…, "依据":…}`，代码把「依据」拿去资料里
**逐字比对**，找不到就判定为"编"。

**实测把这个方案否了**（探针 `core/_probe_chuchu.py`）：三组问题量下来，「依据命中率」
是**反向**的 —— 编造的答案 **92%~100%**，真答案只有 **64%**。
因为编造的"依据"是照抄喂给它的片段，字面当然像；真答案反而是跨块拼出来的。
更本质的是：**「依据是否支撑答案」是语义问题，字面匹配判不了。**

所以最后没留硬拦，改成**把来源摊开**：AI 说的来源它自己能编，
**代码说的来源（= 检索命中哪几节）编不了** —— 让用户对着来源自己核对。

> 完整的排查过程（三次翻车、每次的数据）写在 [TECH-NOTES.md](TECH-NOTES.md)。

## 踩坑记录

这篇是**面试素材**：[**TECH-NOTES.md**](TECH-NOTES.md) —— 按"现象 → 怎么定位 → 根因 → 现在的做法"
记录了：

- **静默错误家族**（程序不报错、结果悄悄不对）：存累计导致总额翻倍、`"w"` 抹掉历史、变量名打错照跑…
- **缩进的一体两面**：多缩进 → 输出重复（白调 3 次 API）；少缩进 → 该出现的不出现（菜单只显示一次）
- **阈值靠量不靠猜**：0.8 被数据推翻，量出空白带定 0.5
- **一次被实测否决的方案**：引用校验防幻觉，判据反向
- **`global` 的三种写法**：函数里清零 / 只搬出去就炸 / 外面 + `global` 才对
- **工具链的坑**：隐形字符、换行符被整文件改掉、含中文文件不能普通替换、IDE 误报

## 维护须知

1. **资料改了，向量库必须重建**：`core/rag2.py` 会重新切块、算向量，覆盖 `core/xiangliang.json`。
2. **换了 embedding 模型也要重建**（新旧向量同维数，混着比**不会报错**，只会静默给出垃圾结果）。
3. **老脚本按"当前所在文件夹"找资料**：`core/` 里的在 `core/` 里跑，`practice/` 里的在 `practice/` 里跑。
   作品本身和 `rag2.py` 已经改成"认文件自己的位置"，换到哪跑都行。
4. **账本存的是"整句原文"**：`zhangben.txt` 每行是用户原话（如 `早饭23`），
   金额由 `zhua_shuzi()` 现抠。老数据（纯数字行 `20`）照样读得进，不用清账本。
5. **改完代码跑验收四件套**：`pylint` → `py_compile` → import 冒烟 → 端到端。
   动过真实数据要先备份。
